# UNI Design System Documentation — Project Context

## What this project is

An Astro + Starlight documentation site for Unifonic's UNI design system. It replaces a static export from Supernova. Content lives as Markdown files; adding new files automatically creates new pages and sidebar entries — no code changes required.

**Live deploy:** Vercel (auto-detects Astro, zero config). Push to GitHub → deploys automatically.

---

## Tech stack decisions

| Decision | Choice | Why |
|---|---|---|
| Framework | Astro 6 + Starlight 0.39 | Best-in-class static docs; built-in search, dark mode, sidebar — zero config |
| Styling | Tailwind CSS v4 (via `@tailwindcss/vite`) | Utility-first; coexists cleanly with Starlight CSS variables |
| Search | Pagefind (built into Starlight) | Zero config, static, works without a backend |
| Fonts | Inter via Google Fonts | UNI's typeface — all heading and body text styles use Inter |
| Images | Stored locally in `public/images/` | Supernova CDN URLs would break; downloaded all 218 images at setup |
| Package manager | Yarn | npm registry was unreachable at setup time |

## Key decisions and gotchas

### Starlight v0.39 sidebar syntax
`autogenerate` must be wrapped in an `items` array. The old syntax throws a config error:
```js
// Correct
{ label: 'Foundations', items: [{ autogenerate: { directory: 'foundations' } }] }

// Wrong — throws "Support for autogenerated sidebar groups was removed in Starlight v0.39.0"
{ label: 'Foundations', autogenerate: { directory: 'foundations' } }
```

### Component tab system
`ComponentTabs.astro` overrides Starlight's `PageTitle` component. It detects tab pages by checking whether the last URL path segment is one of `['overview', 'usage', 'structure', 'code', 'change-log']`, then finds siblings via `getCollection('docs')` filtered by parent path.

Tab files use `sidebar: { hidden: true }` so only the overview appears in the sidebar. The overview file uses `sidebar: { label: "Component Name" }` to show the component name instead of "Overview".

### Storybook embeds
The rehype plugin at `src/plugins/rehype-storybook-embed.mjs` detects `<a>` tags whose `href` contains `iframe.html` and rewrites them as `<iframe>` embeds with `.storybook-embed` wrapper styling.

### Image paths
All images are stored in `public/images/`. Paths in Markdown always start with `/images/filename.png`. The original Supernova CDN URLs were rewritten during migration.

### Frontmatter conventions
- **Single pages:** `title`, optional `sidebar.order`
- **Component overview:** `title: "Overview"`, `sidebar: { label: "Button", order: 1 }`
- **Tab pages (non-overview):** `title: "Usage"`, `sidebar: { hidden: true }`

## Adding new content

**New single page** (e.g. a foundations topic):
1. Create `src/content/docs/foundations/motion.md`
2. Add frontmatter: `title`, `description`, `sidebar: { order: N }`
3. Done — appears in sidebar automatically

**New component** (with tabs):
1. Create folder: `src/content/docs/components/buttons/fab/`
2. Add files: `overview.md`, `usage.md`, `structure.md`, `code.md`, `change-log.md`
3. `overview.md` frontmatter: `sidebar: { label: "FAB", order: N }`
4. All other files: `sidebar: { hidden: true }`
5. Done — sidebar shows "FAB", page shows tab bar

**New top-level section:**
1. Create `src/content/docs/patterns/`
2. Add content files
3. Register in `astro.config.mjs` sidebar array:
   ```js
   { label: 'Patterns', items: [{ autogenerate: { directory: 'patterns' } }] }
   ```
